# 以 OMEGA-OS 为体验基准的开发流程

## 基准定义与证据

参考仓库：[omgupta117/OMEGA-OS](https://github.com/omgupta117/OMEGA-OS)。
本次核对固定在提交 [`a4e2a52e3b5ce1c2f0f0161c8dea624bd553c7f0`](https://github.com/omgupta117/OMEGA-OS/tree/a4e2a52e3b5ce1c2f0f0161c8dea624bd553c7f0)，后续上游变化必须单独更新基准，不随 HEAD 自动漂移。
已核对 README、HTML、CSS 和 JavaScript；尚未进行浏览器交互与截图复核，参考体验不能标记为运行验收通过。

OMEGA 是浏览器内的桌面模拟器；Matrix 的目标是运行真实应用的 Linux 桌面。
采用它的深色未来感、界面层次和完整交互场景作为体验基准，继续采用 **Wayland + KWin + Qt Quick/QML**。
性能仍按 [同机 Windows 协议](performance.md)验收，不能由 OMEGA 的 README 中“60fps”声明推导实际性能。
不引入 WebView 来承载主桌面，也不移植它的 DOM 窗口管理器。

| 参考证据（固定提交内的路径/符号） | 源码可确认的行为 | Matrix 的对应要求 |
| --- | --- | --- |
| `style.css` `:root`、`.glass-panel` | 黑底、青/紫强调色、玻璃面板、发光、300ms 常用过渡 | QML 视觉令牌、统一层次、清晰焦点；重特效有降级路径 |
| `index.html`、`script.js/initStartMenu`、`js/AppManager.js` | 应用网格、菜单开关与应用窗口创建；搜索框存在，未见搜索处理器 | 真正的应用发现、过滤、启动与启动失败反馈 |
| `js/WindowManager.js` | 拖动、最小化、最大化、任务栏切换和边缘吸附 | 通过 KWin 管理真实客户端，验证窗口状态和任务栏一致性 |
| `script.js/notify`、`initNotificationCenter` | 提示、通知历史与清空 | 实现 freedesktop 通知服务语义，避免与已有服务争抢 |
| `js/AppTemplates.js/initFiles` | localStorage 虚拟目录，创建/删除；打开文件只提示 | 真实目录、文件操作、取消、权限与冲突错误、可恢复删除 |
| `js/AppTemplates.js/initNotes`、`initCalculator` | 本地笔记持久化与计算器逻辑 | 标准应用启动及持久化体验；可集成成熟 Linux 应用 |
| `js/AppTemplates.js/initTaskMgr` | 浏览器窗口列表；CPU/RAM/PID 使用模拟数据 | 可追溯真实进程和指标，明确权限，不能把关闭窗口当结束进程 |
| `js/AppTemplates.js/initStore` | 延时后向菜单注入应用项 | PackageKit/Flatpak 等受支持后端的真实安装状态及失败/取消反馈 |
| `script.js/initLockScreen` | 任意输入可解锁 | 仅参考过渡体验；锁屏必须由可信会话锁定/认证组件负责 |
| `js/AppTemplates.js/initSettings`、`script.js/playSound` | 强调色变更、合成音效；颜色未见持久化 | 设置持久化、静音/音量、减少动态效果与低特效模式 |
| `js/AppTemplates.js/initTerminal`、`initWeather`、`initAI` | 命令分支、模拟天气、语音/规则式响应 | 终端必须是真实终端；天气/AI 为明确的后续扩展，有真实数据来源才称可用 |

本次只研究行为，不复制上游代码或素材；检出中未发现 LICENSE。若未来需要复用，先确认授权。
参考截图与录屏的采集步骤见下文；本次没有把源码观察描述成浏览器实测。

## 验收范围

`acceptance.json` 是验收项、阶段、状态与证据的唯一结构化清单。每个变更引用稳定 ID。
`partial` 表示只有一部分行为存在，`planned` 表示未实现；`verified` 必须有执行证据和人工复核。
完整桌面发布要求所有 `required` 项达到 verified；部分阶段完成只能称该阶段通过。
`extension` 项不阻塞首个完整桌面版本，但必须在范围说明中列出，不得无声删掉。

| 阶段 | 本阶段可交付结果 | 验收项 | 依赖与退出条件 |
| --- | --- | --- | --- |
| M0 基准冻结 | 上游静态清单、可复现的参考录屏和设计稿 | REF-01 | 先完成浏览器复核、固定视觉样例与审核记录，才能判定视觉对齐 |
| M1 壳与视觉 | OMEGA 风格令牌、桌面布局、应用启动器、键盘/可访问性、设置 | UX-01、APP-01、CFG-01 | 真实应用启动成功；首屏、菜单、空/错误/载入状态全覆盖 |
| M2 会话集成 | 桌面层、面板保留区、真实窗口列表和控制、多屏 | WIN-01、DISPLAY-01 | 在隔离的 KWin 会话验证，不替换用户当前桌面；固定兼容版本后进入 gate |
| M3 工作流闭环 | 文件操作、通知、系统状态、基础应用体验 | FILE-01、NOTIFY-01、SYS-01、APPS-01 | 数据和进程状态必须真实；重启持久化与错误路径通过 |
| M4 发布候选 | 性能、会话锁定/恢复、真实应用安装 | PERF-01、SESSION-01、STORE-01 | 同机 Windows 负载验收和恢复演练通过；所有 required 项复核 |
| 扩展 | 天气、AI、游戏、代码编辑器等 | EXTRA-01 | 不挤占主线；每项单独声明后端、凭据、许可和验收范围 |

阶段可以开展独立预研，但不跨越缺失依赖宣布完成。每项拆为一个可评审 PR；较大项拆为适配器、模型、界面、集成测试几个连续 PR。
首个建议任务是 APP-01：用受控测试 `.desktop` fixtures 做应用发现/过滤/启动，再接真实应用目录；不要继续把目录菜单称为应用启动器。

## 视觉与操作验收协议

1. 在受控浏览器中检出固定 OMEGA 提交，通过本地静态 HTTP 服务加载。记录浏览器、系统、字体、缩放、窗口尺寸、时间、外部资源状态和控制台错误。其 Google Fonts/FontAwesome 依赖需记录加载成功或离线回退，不能暗改后作为原始基准。
2. 采集桌面、开始菜单、两个重叠窗口、最小化/恢复、左右吸附、通知、文件目录、设置和锁屏过渡的截图/录屏。已观察故障记录为上游限制，不把故障照搬成 Matrix 通过条件。
3. 建立 Matrix 设计稿：黑蓝背景、青色主强调、紫色辅助强调、统一玻璃面板层次。文字对比度按 WCAG AA（普通文字 4.5:1，大文字 3:1）；焦点清晰，不仅靠颜色表达状态。
4. 主视觉样例固定为 1920×1080@100%、2560×1440@150%；另测 1280×720、小预览窗口 360×480、100%/125%/150%/200% 缩放与双屏混合缩放。使用固定测试数据、时间、字体和壁纸，屏蔽光标闪烁后生成回归截图。
5. 截图与审核过的 Matrix golden 比较，不与浏览器 DOM 做逐像素强制等同。审核布局层次、对齐、文字截断、图标语义、焦点、载入/空/错误状态；golden 更新必须附前后图和变更原因，不能失败后直接覆盖。
6. 打开/关闭、悬停、切换采用统一动效；常规过渡候选 120–200ms，需实测调整，不复制阻塞启动的演出动画。减少动态效果时不做大幅位移；低特效关闭模糊、粒子与光晕，不影响功能。
7. 每个场景录制鼠标与键盘两条路径；增加中文输入法、读屏器、触屏、长名称与大字体检查。当前 offscreen 测试只验证部分键盘/焦点行为。

## 每个任务的自动开发闭环

1. **选择验收 ID**：写明目标用户操作、已有证据、当前缺口、前置依赖和不包含的范围。
2. **先定义可失败的验收**：Given/When/Then；标明 CI、KWin、visual、hardware、session 中哪些 gate 必须执行及原因。
3. **先验证接口**：涉及窗口/快捷键/桌面角色时，先记录 KDE、KWin、Qt、驱动与协议版本。普通 Wayland 客户端不能任意枚举/控制其他客户端；评估 Plasma 组件或特权受控桥接，禁止假设通用 layer-shell 就能管理窗口。
4. **实现最小垂直切片**：接口/适配器 → 后台数据模型 → QML → 异常与恢复路径。测试 fixtures 与真实服务分离，模拟数据只用于测试且有明确标识。
5. **自动检查**：运行 `./tools/check.sh`、构建 wheel；上传 JUnit 和构建产物。基础 CI 通过只意味着代码 gate 通过。
6. **场景验证**：按 ID 执行缺失的集成/视觉/实机 gate；附提交 SHA、runner/硬件、命令、原始数据、结果和已知问题。未运行写 unrun；故障写 failed，不用 skipped 冒充通过。
7. **PR 复核**：使用模板列出 ID、实现行为、证据与缺口。所有本次必需 gate 通过才称相应行为 verified；基础 CI 不自动勾选完整桌面验收。
8. **回归与发布**：合并后在固定系统镜像重跑集成场景；发布候选重复性能和恢复协议，人工审核后发布。自动化不自行合并、发布或更换默认桌面。

## 分层 gate 与执行环境

| Gate | 执行环境 | 必需检查 | 当前能力 |
| --- | --- | --- | --- |
| ci | GitHub 托管 Linux、offscreen | 后台模型、请求竞争、交互、验收清单结构、QML 帧提交、wheel | 可执行；不能证明 Wayland/GPU |
| kwin | 固定 KDE/Qt 版本的隔离 VM/专用会话 | 真实应用、焦点、任务栏、吸附、保留区、多屏、热插拔 | 待建设，不从公网 PR 自动运行特权 runner |
| visual | 固定字体/屏幕/数据的参考机 | golden 前后图、主题/动效降级、键盘、读屏与输入法 | 待建设；人工复核在自动视觉比较之后 |
| hardware | 实机双系统、60/120Hz | 同机 Windows 对照，复制/CPU/GPU 压力，P95/P99、功耗、延迟 | 待采集，详见 performance.md |
| session | 可回滚 VM + 实机 | 退出、崩溃重启、锁屏认证、恢复、升级/回滚 | 待建设；截图无法验证隔离与认证 |

KWin/hardware/session runner 只在受控的手工触发或审核后的提交上运行；不要给不受信任的 PR 代码开放长期特权 runner。
分支保护需在 GitHub 仓库设置里将 `development-gates / check` 设为 required check；本次只提交工作流，不声称已启用保护。
尚未实现的 gate 不放置永远成功的占位 job；其执行状态写入 PR 和证据记录。

## 证据与进度管理

建议证据目录：`artifacts/<Matrix提交SHA>/<验收ID>/<运行ID>/`，由 CI 上传或存到审阅者能访问的记录中。
每份结果至少记录：Matrix SHA、OMEGA SHA、场景、环境版本、屏幕/电源条件、测试命令、开始时间、结果、原始数据链接与复核人。
仓库不提交敏感日志、个人目录截图或大录像；结构化清单中的 evidence 记录可访问的 CI run/报告/审核记录链接。

`python3 tools/acceptance_report.py` 显示整体缺口；`--check` 验证清单结构及证据字段，**不执行桌面场景，也不授予验收通过**。
只允许 planned → partial → verified 的证据驱动推进；回归时退回 partial 并附失败记录。
上游基准更新需要单独 PR：新旧 SHA、场景变化、视觉差异、受影响验收 ID、是否需更新 golden；不得趁版本漂移降低原有指标。

Definition of Done：本次 ID 的行为与错误路径可演示、所需 gate 通过、证据完整、文档一致、复核完成。
完整桌面发布额外要求所有 required 项 verified；可选应用数量和综合得分不能抵消某个必需功能失败。
